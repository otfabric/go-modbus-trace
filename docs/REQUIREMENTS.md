# Requirements: go-modbus-trace

Version 0.1 scope. Supersedes the original "Modbus Capture" proposal (live capture, daemon, browser); the reasons are in the application repository's `docs/PROPOSAL-REVIEW.md`. Priorities: **MUST** (v0.1.0), **SHOULD** (v0.1.0 if time allows, else v0.2). Milestones L0..L4 are defined in `ARCHITECTURE.md` section 12. Facts marked *(verified)* were checked in the local checkouts of go-modbus-capture v0.0.2, modbusctl v3.2.0 and go-modbus v1.7.1 on 2026-10-15; facts marked *(unverified)* must be checked in the milestone named.

## Scope

Read a packet trace recorded by someone else, find Modbus/TCP in it, and produce (a) a faithful, time-ordered event stream with provenance, (b) bounded-memory analysis, and (c) exports: MBCAP for replay, timeline CSV/JSONL, and a pcapng sub-trace. One engine serves the CLI `mbtracectl` and the Wails application.

**Non-goals for v0.1**: live capture or any network I/O; sending Modbus; TCP packet replay; decoding register values into engineering units; Modbus/TCP Security (TLS), RTU-over-TCP, Modbus/UDP, serial RTU/ASCII (detected and reported as such where cheap, never decoded); decryption; tunnels (GRE, VXLAN, IPsec) beyond counting them; a database; a GUI (that is the application).

## Requirements

| ID | Pri | M | Requirement |
|---|---|---|---|
| L1 | MUST | L1 | **Input formats.** Classic pcap (magic `a1b2c3d4` and nanosecond `a1b23c4d`, both byte orders) and pcapng (Section Header, Interface Description, Enhanced Packet, Simple Packet, Interface Statistics; Name Resolution, Decryption Secrets and unknown blocks skipped; several sections; several interfaces with their own link type, `if_tsresol` and `if_tsoffset`). Format detected from the first bytes, never from the file name. gzip detected by magic and read transparently. Input from a path or an `io.Reader` (stdin). A truncated last record or block is tolerated with a quality warning; a corrupt classic-pcap record header ends the read with the results so far and an error that says so; a corrupt pcapng block whose length is still plausible is skipped and counted. Simple Packet Blocks carry no timestamp: counted, used for flow state, never for timing. |
| L2 | MUST | L1 | **Link and network layers.** Link types: Ethernet (1) with 802.1Q and QinQ tags, BSD loopback (0, 108), raw IP (101), IPv4 (228), IPv6 (229), Linux cooked SLL (113) and SLL2 (276). IPv4 with options; IPv6 with extension headers (hop-by-hop, routing, destination options, fragment) skipped correctly. Anything else (other link types, AH/ESP, tunnels, non-TCP) is counted by reason and listed in the file summary, never silently ignored. IPv4 and IPv6 fragment reassembly with bounded buffers: MUST for IPv4 and IPv6 (L0: one shared reassembler, IPv6 adds about 10 lines; built in L1 together with IPv4, `DECISIONS.md` D4; promoted to MUST by the user 2026-10-15). TCP and IP checksums are not validated (offload). |
| L3 | MUST | L1 | **Connections.** Identified by the direction-independent 4-tuple plus an **epoch**: a new epoch starts at a SYN (not a retransmitted one) after the previous epoch saw FIN or RST, or at a SYN whose sequence number is outside the old epoch's window. Midstream starts (no SYN seen) are supported and flagged. Per connection: client and server endpoint, role confidence and source, first and last packet time, how it opened and closed (SYN, midstream; FIN, RST, end of trace, evicted), first interface, packet and byte counts per direction. The same 4-tuple on two interfaces is reported, not merged by interface. |
| L4 | MUST | L1 | **TCP reassembly.** Per direction, in order. Segments before the expected sequence number (retransmissions, keepalive probes) are dropped and counted; segments after it are buffered up to a limit; a gap is declared when the limit is exceeded, when the peer acknowledges bytes that were never captured (they will not be retransmitted), at FIN/RST, or at the end of the trace, and carries the number of missing bytes when the sequence numbers give it. Overlaps: first data wins (as Wireshark), a conflicting overlap is flagged. Duplicate observations of the same packet (`-i any`, two taps, bridge and member interface) fall out as retransmissions and must not duplicate any transaction. TCP segment boundaries are never message boundaries. Window scaling, SACK and options are ignored except where they affect sequence arithmetic (sequence wraparound is handled). |
| L5 | MUST | L1 | **MBAP framing.** Per direction: 7-byte header (transaction ID, protocol ID = 0, length, unit ID), length 2..254 (PDU 1..253 bytes; ADU at most 260 bytes), several ADUs per segment, one ADU over several segments. A bad header or a gap puts the framer into **resync**: bounded scan (default 64 KiB) for a position where a valid header is followed by a valid next header, or where header and function match an outstanding request. A resync is an event with a confidence value; an ADU found after a resync is flagged and never trusted for MBCAP. The first ADU of a midstream trace is tried at offset 0 first. |
| L6 | MUST | L1 | **Roles.** Server and client endpoints of each connection are decided by, in order: user override (`ServerPorts`, `Servers`, `Clients`, per-flow); the SYN direction; a configured server port (default 502); the structure of the traffic (which orientation makes requests parse as requests and responses pair with them). The deciding source and a confidence are recorded. An undecidable connection is reported as `unknown` and is not exported. |
| L7 | MUST | L2 | **PDU decoding.** Structural decode and validation of requests *and* responses for every function in the coverage matrix (`docs/COVERAGE.md`, generated from the code and tested): FC01-06, 07, 08 (all sub-functions, data-returning ones decoded), 11, 12, 15, 16, 17, 20, 21, 22, 23, 24, 43 (MEI 14 decoded, other MEI types opaque), and exception responses. Unknown and vendor function codes: preserved as opaque with the function code and length. Validation per the Modbus Application Protocol V1.1b (quantity limits, byte-count consistency, fixed lengths); a violation is a warning on the transaction, never a dropped transaction. Addresses are the raw zero-based 16-bit PDU addresses; no 1-based form in the library. FC03/04 (and FC01/02) responses carry no address: it is derived only from the matched request. FC23 has separate read and write ranges. Functions without a range get no invented address or quantity. A function normally limited to serial lines (FC07, 08, 11, 12, 17) seen over TCP is decoded and labeled `serial_function_over_tcp`. Every decoded field carries its **byte range** within the ADU (for highlighting in a hex view), and the decoder offers a helper that returns the raw word or bit at a given address from a decoded read response and its request range (used for address history). A one-line English summary helper ("Read 62 holding registers @ 4096") is exported for display use. |
| L8 | MUST | L2 | **Pairing.** Per connection: a request is matched to the oldest outstanding request with the same unit ID and transaction ID whose function code equals the response's (or the response's with bit 0x80 set for an exception). Pipelining and out-of-order responses between different transaction IDs are supported. Statuses: `ok`, `exception`, `unanswered` (no response before the connection ended, the transaction ID was reused, or the trace ended; it does not mean the device failed), `orphan_response` (no outstanding request: midstream start or lost request), `ambiguous` (several outstanding requests with the same key *and different request PDUs*), `malformed`, `uncertain` (touched by a gap or resync). A repeated request with the same ID and byte-identical PDU is a `retried` flag, not `ambiguous`. A response with a timestamp before its request (merged traces, skewed clocks) is flagged `clock_order`. A late response still pairs; slowness is a latency threshold (default 1 s, configurable) flag `slow`, not a status. |
| L9 | MUST | L2 | **Event model.** Events: `conn.open`, `conn.close`, `txn` (every status above), `gap`, `resync`, `trace.note` (e.g. pcapng interface drop statistics, snaplen truncation, unsupported encapsulation). Every transaction carries: connection ID, server endpoint, unit ID, MBAP transaction ID, function and sub-function, **class** (`read`, `write`, `other`), the **range** it touches (data space coil/discrete/holding/input/file/fifo/other, start, count; plus the write range of FC23), request and response ADU views (raw bytes by reference, decoded fields, warnings), request first/last and response first/last packet times (nanoseconds), latency (request last byte to response first byte), status, quality flags (`retransmitted`, `out_of_order`, `gap_adjacent`, `snaplen_truncated`, `midstream`, `role_guessed`, `resynced`, `retried`, `clock_order`, `slow`), and **provenance**: for request and response, the list of packets that carried it (1-based frame number as Wireshark counts them, file offset of the record, interface ID, timestamp, payload offset and length within the packet). Events are emitted in order of determination (a transaction when it completes); consumers sort by the transaction's request time. JSON form with `schema_version`, published as JSON Schema (L22). The library exports a constant `EventSemanticsVersion` that changes whenever the meaning of events changes, so applications can invalidate their caches. |
| L10 | MUST | L1 | **Scan.** A first, cheap pass that returns the file summary (format, link types and interfaces, packets, bytes, first/last time, snaplen and the number of packets with `caplen < origlen`, pcapng drop counters, unsupported-encapsulation counters, SHA-256 of the file computed while reading) and a **flow table** of TCP flows with a Modbus score: candidate if either direction carries valid MBAP headers (protocol ID 0, plausible length, plausible function) in a run of at least 3 ADUs or in at least 90% of ADUs; the score, the ADU counts and the guessed ports are reported. Flows that start with a TLS record (`0x16 0x03`) are classed `tls` (Modbus/TCP Security: not decodable). Non-standard ports (1502, 5021, ...) are found this way. |
| L11 | MUST | L4 | **Analyzers** (streaming, bounded, each with a documented cap and an overflow counter): `overview` (counts by status and function, quality counters, duration); `devices` (per server endpoint and unit: transactions by function and status, clients seen, first/last, bytes, latency histogram with p50/p95/p99/max); `patterns` (per client, server, unit, function and request PDU: count, first/last, inter-request interval median/min/max/jitter, response volatility = share of polls whose response differs from the previous one); `coverage` (per server, unit and data space: merged address intervals read and written with counts and first/last time). |
| L12 | MUST | L2 | **Selection.** One predicate type used by the CLI, the exporters and the application: servers, units, clients, connections, functions, statuses, read/write class, quality flags (require / exclude), time window, address range (data space + range). A selection applied to a transaction decides export and listing; it never alters decoding. |
| L13 | MUST | L3 | **MBCAP export** exactly as specified in `MBCAP-EXPORT.md`: reads only, matched and library-valid pairs only, `Header.Exceptions` on by default, one target per server endpoint and unit, one stream per target and client address, the exclusion report, deterministic output, binary/JSONL/long CSV through go-modbus-capture's writers. The admission decision is a public function `Classify(txn) Reason` with stable reason codes, and the exporter uses exactly that function, so an application can store and preview the decision without running an export. |
| L14 | MUST | L2 | **Timeline export** as CSV and JSON Lines (one row/line per event; raw request and response PDUs as hex; all fields of L9 flattened; documented columns and a published schema for the JSONL form). Ordered by request time with `--order time` (bounded reorder buffer, default 60 s of trace time; late events are emitted anyway and counted) or by determination order with `--order file`. |
| L15 | SHOULD | L4 | **Sub-trace export.** Write the packets of the selected connections, optionally clipped to a time window, as a pcapng file that Wireshark opens: original timestamps and link type, interface descriptions preserved, a comment naming the tool and selection in the section header. Packet payloads are copied verbatim (including writes and vendor functions). |
| L16 | MUST | L2 | **Random access to provenance.** `File.Frames(refs)` re-reads the referenced packets of an uncompressed file by offset (cheap, concurrent-safe) so an application can show raw bytes without keeping them. For gzip or stream inputs it returns a clear `ErrNotSeekable`. |
| L17 | MUST | L1 | **Resource limits and robustness.** Configurable limits with defaults: concurrent connections tracked (default 100,000, least-recently-seen evicted and counted), reassembly buffer per direction (1 MiB) and in total over all connections (64 MiB; when it is exceeded the direction with the most buffered bytes declares its gap, counted), outstanding requests per connection (256), resync scan (64 KiB), patterns tracked (10,000), coverage intervals per space (4,096), fragments buffered (bounded). Memory use is independent of trace size for the streaming path. Cancellation through `context.Context` at packet granularity. A panic in decoding a packet is recovered, counted as `internal_error` with the frame number, and processing continues. |
| L18 | MUST | L1-L4 | **CLI `mbtracectl`** (names and flags proposed): `info`, `flows`, `summary`, `timeline`, `export mbcap`, `export timeline`, `extract`, `version`. Input path or `-`; several input files given in time order are one continuous trace. Output encoding by extension or `--format`. `--json` machine output. Exit codes 0 success, 1 failure, 2 usage (as mbcapctl; modbusctl's finer codes do not apply to a file tool; `docs/exitcodes.md`). Safe outputs (temp file, rename; refuse input-as-output). Follow modbusctl's conventions (`docs/exitcodes.md`, `docs/json-output.md`). Progress on stderr only when it is a terminal. |
| L19 | MUST | L1 | **Portability.** `CGO_ENABLED=0` for every target of "Programs"; the Linux binaries are statically linked and run unchanged on Debian 11, 12 and 13. `go list -deps` of the library contains no cgo package. |
| L20 | MUST | L1 | **No network, no live capture.** Enforced by lint (AGENTS.md) and a test over `go list -deps`. |
| L21 | MUST | L3 | **Determinism.** Same input and options give byte-identical event JSON, timeline and MBCAP exports across runs and across platforms (map iteration, goroutine scheduling and platform line endings must not leak). |
| L22 | MUST | L4 | **Schemas.** JSON Schema (draft 2020-12) in `docs/schema/` for the event/transaction JSON, the file summary, the flow table, every analyzer result, the export report and the CLI JSON output. Tests validate real output against them; a change of a `model/` type that is not made in the schema fails the build. |
| L23 | SHOULD | L1-L4 | **Performance envelope** *(proposed targets; L0 measures and the numbers are recorded in `docs/ARCHITECTURE.md`)*: the `flows` scan at least 200 MB/s per core and the full analysis at least 100 MB/s on a Modbus-dominated trace on an Apple M-series core; resident memory under 300 MB at default limits for any trace size; a 1 GB trace analyzed in under 30 s on a laptop. Throughput and allocation benchmarks run in CI (reported, not gating until baselined). |
| L24 | MUST | L2-L4 | **Documentation.** `docs/COVERAGE.md` (function coverage matrix, generated), `docs/REPLAY-WORKFLOW.md` (trace to virtual device, section 6 of `MBCAP-EXPORT.md` is the source), godoc on every exported identifier, a README that shows the three commands that matter (`flows`, `summary`, `export mbcap`) on a bundled fixture. |

## Acceptance tests

Test infrastructure is described in `TESTING.md`. Every test runs without privileges and without network access.

| ID | Test |
|---|---|
| LA1 | Reader fixtures: pcap microsecond and nanosecond, little and big endian; pcapng with two interfaces of different link types and `if_tsresol`; a Simple Packet Block; a truncated last record; a gzip file; an unknown pcapng block; a corrupt block in the middle (skipped, counted); stdin streaming gives the same events as the file. |
| LA2 | Each supported link type (Ethernet, 802.1Q, QinQ, BSD loopback, raw IP, IPv4, IPv6, SLL, SLL2) carries the same conversation and yields identical events apart from frame provenance; unsupported encapsulations are counted by reason. |
| LA3 | Reassembly ground truth from the synthetic builder: ADU header split over segments, several ADUs in one segment, one-byte segments, retransmission, out-of-order, identical overlap, conflicting overlap, midstream start, loss (gap), duplicated packets from two interfaces, SYN retransmission, FIN, RST, 4-tuple reuse (two epochs), keepalive probes, sequence wraparound. The decoded transactions equal the script's, with the expected quality flags, and no duplicates. |
| LA4 | Framing: bad protocol ID, length 0/1/255+, a resync that succeeds on the next valid header, a resync that fails within the scan limit, 2 MiB of junk (bounded work), a trace that starts in the middle of an ADU. |
| LA5 | Roles: by SYN, by port, by structure, by user override, undecidable (reported `unknown`, not exported); a non-standard port is found by `Scan` and decoded once selected; a TLS flow is classed `tls`. |
| LA6 | PDU coverage: for every function in the matrix, golden request and response decodes; frames *generated by go-modbus v1.7.1* (its client against its server, which serves every function) for every function it supports, including FC08 sub-functions, FC20/21/24, FC43/14 paged reads and exceptions; the decode equals the API-level values the client returned. Vendor and unknown functions stay opaque. Validation warnings for each documented violation. |
| LA7 | Pairing: parallel clients with the same transaction IDs on different connections, units sharing transaction IDs, pipelining, out-of-order responses, reused IDs, a retried identical request, an ambiguous different-PDU pair, an orphan response, an unanswered request at connection end, a slow response, a response before its request. |
| LA8 | Quality accounting: counters in the file summary and per transaction equal the synthetic ground truth for every condition above. |
| LA9 | MBCAP export: the admission matrix of `MBCAP-EXPORT.md` section 3 holds row by row (writes, FC23, vendor, FC08 state-changing, MEI other than 14, orphan, ambiguous, uncertain, truncated never appear; supported reads and their exceptions always do); `mbcapctl verify` passes on binary, JSONL and CSV output; `capture.Equal` holds across the three encodings; the report's counts add up to the number of transactions seen. |
| LA10 | Replay end to end: a synthetic client polls a go-modbus server whose registers follow a known script; the traffic is turned into a trace; `export mbcap` runs; `modbusctl server replay --before-first absent --missing exception` (and `server static --at`) is started on the result; a go-modbus client reading it gets exactly the scripted values at the scripted times (within one sample interval), an exception for never-read addresses, and the identity objects of a paged FC43. Uses the pinned releases of mbcapctl and modbusctl; skipped with a clear message when the binaries are absent, required in CI. |
| LA11 | Determinism: two runs, and a run on a different OS/architecture in CI, produce byte-identical timeline and MBCAP files; CLI output equals library output. |
| LA12 | Sub-trace: extract a connection and a time window; re-analysis of the output yields the same transactions for that connection; the file opens with `tshark -r` where tshark is installed (optional). |
| LA13 | Oracle (advisory CI job): on the same fixtures, `tshark -T fields` agrees with our transactions on transaction ID, unit, function, reference number, word count and request/response linking. Field names are checked against the installed tshark first (`tshark -G fields`). Disagreements are triaged, not auto-fixed. |
| LA14 | Fuzzing and bounds: native Go fuzz targets for both readers, link/IP/TCP parsing, the framer, every PDU decoder and the whole pipeline pass their seed corpora in CI and a time-boxed run; no panic escapes; a 5 GB synthetic stream (generated, not stored) is processed with flat memory under default limits. |
| LA15 | Build matrix: `CGO_ENABLED=0 go build ./...` for every target; `file` reports static Linux binaries; `go list -deps` shows no cgo, no `net/http`, no `os/exec` in non-test, non-CLI code. |
| LA16 | Provenance: for sampled transactions, `File.Frames` returns packets whose payload bytes reassemble to the ADU the event reports; gzip input returns `ErrNotSeekable`. |
| LA17 | CLI: exit codes, `--json` output validates against the schemas, stdin streaming (`... | mbtracectl export mbcap - -o out.mbcap`), several input files as one trace, refusal of input-as-output, no partial output file after a failure or Ctrl-C. |
| LA18 | Benchmarks for L23 are recorded in `docs/ARCHITECTURE.md` with the machine and the commit; a regression of more than 20% is reported by CI. |
